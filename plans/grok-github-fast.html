Build order

Each stage has a user-visible win and can stop the project. Do not start a relay before Stage 0–1.

0

Stop paying for unchanged bytes

Disk-cache conversation like the patch cache. Cheap REST skip before GraphQL. No new daemon.

Win: a 30-minute review is no longer ~60 identical gh spawns.
1

Process-wide replica

SQLite summaries + conversations + checks. HTTP client. Shared across worktrees of the same slug.

Win: inbox/list ≤ 30 ms warm. next.js-scale list cannot 504.
2

Mutation queue

Pending overlay. Refetch before clear. No auto-retry on POST comments. Merge snapshot.

Win: comments feel instant; no duplicate-comment bug.
3

Mirror for missing blobs

Fetch one pull ref with blobs. CodeView sides from git. GitHub patch remains the line map.

Win: file sides open when GitHub 406s the unified diff.
4

Optional live push + listen

Relay or notifications ETag. IPC listen. Loopback HTTP still off.

Win: teammate comments without the 30–90 s poll. Agents do not burn quota.

Do not do

  1. Embed github.com or cache its HTML.
  2. One GraphQL document for a whole PR (the 504).
  3. Packfiles in SQLite.
  4. Webhook payload as the database.
  5. Optimistic merge.
  6. git diff as the GitHub line map.
  7. blob:none as the review fetch.
  8. Auto-retry POST comments.
  9. Copy ETags across token rotation.
  10. Replace repo pr list with involves:@me.
  11. Fetch all refs/pull/*.
  12. Block Welcome on GitHub.
  13. Auto-advance a frozen patch tab.
  14. Agent gh api proxy.
  15. Call it a local GitHub in the UI.
